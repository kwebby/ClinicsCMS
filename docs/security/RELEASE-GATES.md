## Evidence from a fresh clone

Generated reports and credentials are not shipped in the public repository. The [implementation status](../IMPLEMENTATION-STATUS.md) summarizes dated local observations and explains how to generate new evidence. The [development guide](../DEVELOPMENT.md) documents disposable test targets, optional Redis-backed authentication tests, browser prerequisites, and report generation. A passing memory suite or skipped integration suite is not evidence for an untested database.

Keep detailed test, recovery, and penetration-test reports in a restricted operations store with the tested commit, configuration, date, and responsible reviewer. Publish only reviewed synthetic summaries. GitHub Actions run artifacts are generated by their individual jobs; creating or cloning the workflow does not produce them.

## Independent penetration-test scope

Provide the external tester with synthetic seeded users for every role, at least two branches, unrelated patients/caregivers, signed and draft encounters, held/released files, open/issued/refunded invoices, payroll runs, uploaded themes, and patient/staff conversations. Include authenticated and unauthenticated testing of APIs/sockets, authorization, identity linking/MFA/revocation, CSRF/origin handling, stored content/ZIP handling, upload/download controls, payment/webhook business logic, AI/proxy boundaries, deployment configuration and recovery flows. Commissioning access, credentials and real host targets are operator actions; no external testing or scanning is implied by running this repository's tests.

## Troubleshooting and staff checks

- Upload fails: inspect scanner health and definitions, MIME/size limits and quarantine error code; never bypass production scanning.
- AI fails: inspect provider configuration/policy/quota and provider status using redacted request IDs; do not paste patient content into public logs.
- Payment unresolved: inspect signature verification, event deduplication and invoice reconciliation; checkout redirects alone are not payment evidence.
- Reminder missing: distinguish pending/retry/SMTP-accepted/confirmed delivery; update owner/escalation rather than silently dropping work.
- Patient cannot see a document: verify identity link, explicit release, membership/branch permissions and session freshness; do not grant a staff role to solve access problems.
- New page not visible: publish the page, then publish the website to bind its approved snapshot. Inspect canonical/slug and active publication; use rollback to recover exact prior content/settings/theme.

Train reception on registration identity, walk-ins, rescheduling and callbacks; clinicians on drafts, signatures/amendments, result ownership/coverage and AI review; finance/HR on invoice/pay-run approval and reconciliation; editors on clinical review, schema/social fields and theme publication; administrators on roles/MFA, scanners/provider failures and tested recovery.

## Delivered CI gates

`.github/workflows/ci.yml` pins Node and GitHub actions and runs lockfile installation, typechecking, regression tests, application build, production dependency audit, a license allowlist, checksum-verified Gitleaks and Trivy, application-image build/scan, and an SBOM artifact. Missing scanner binaries, unapproved licenses, and High/Critical scan findings fail their steps. Separate service jobs run the contract suite against PostgreSQL 17/18 and MySQL 8.4. Manual jobs require a dedicated protected `disposable-certification` environment and explicit Supabase/real-Firestore secrets; they never silently substitute the emulator or an in-memory result for a remote-backend run.

Creating this workflow is not evidence that it has run. Linux host/proxy deployment, real remote-database certification, production provider checks, recovery timing, clinical acceptance and independent penetration testing remain separate evidence gates. Retain package/image license notices and satisfy any applicable source/redistribution obligations; the license allowlist is a review gate, not legal clearance.
