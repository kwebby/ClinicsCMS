# ClinicsCMS platform API integration

ClinicsCMS exports platform services from `packages/platform/src/index.ts` using relative ESM imports. The [shared API contract](API-CONTRACT.md) documents HTTP routes; this page describes server-side integration. All methods throw `DomainError` with a safe message/status. Callers must preserve the authenticated server-derived Actor; never use an actor supplied by a browser. JSON entities use the common Repository interface.

- `new ThemeService(db, {root, scanner?})`: `importZip(buffer, actor)`, `exportZip(id, actor)`, `preview(id, actor)`, `activate(id, actor, expectedPublicationId?)`, `rollback(actor, expectedPublicationId?)`, `publicSite(organizationId)`, `asset(themeId,path,organizationId,actor?)`. Read-only preview returns manifest/assets; publication returns an immutable revision and pointer. `publicSite` resolves bound immutable `pages` and `settings:{business,website}` (null only before the first website activation); public routes must use these instead of current drafts/settings. The published site is cached per organization by publication ID and returned deeply frozen; callers must copy before changing it. Every call still reads the publication pointer, so publishes and rollbacks from any process take effect immediately. Activation pages through all pages, settings and permanent routes, so location slug conflicts are checked against every row. Imported PNG/JPEG/WebP assets are decoded and re-encoded in the same format (metadata and trailing bytes removed); WOFF2 headers are validated. `THEME_PATHS`, `isThemeFilePath` and `isThemeDirectoryPath` are the archive path rules shared with `pnpm theme:package`. ZIP multipart limit is 25 MiB before service entry. Theme assets live in private local storage and are served only through this service. All imports require malware scanning; the explicit test scanner is only for tests.
- `new LocalFileStorage(db, {root, scanner?, maxBytes?})`: `upload({bytes,name,mime,patientId?,scope?}, actor)`, `read(id,actor)`. Uploads are always private, scanned before DB visibility. `scope` is `clinical`, `conversation`, `personal`, or `payroll`; MIME comes from verified signatures and supplied MIME must match. `patientId` is required for `clinical`, allowed for `conversation` only when the patient exists and is within the uploader's own patient or branch scope (otherwise `403`/`404`), and rejected with `FILE_SCOPE` for `personal`/`payroll`. `read` returns `{record, bytes}`. HTTP must send attachment disposition and nosniff; never static-mount root.
- `ClamAvScanner` implements `scan(path): Promise<void>`; fail closed on missing scanner, malware, or errors. A signature match (clamdscan exit 1) throws `FILE_SCAN_FAILED` (422); a missing client, unreachable daemon, timeout or other scanner error throws `SCANNER_UNAVAILABLE` (503), so clients can retry later instead of reporting malware. Its `clamdscan --stream` command runs without a shell and sends bytes to the private scanner service. File APIs are for authenticated users only.
- `buildSeo(page, site)` returns `{title, description, canonical, robots, openGraph, twitter, alternates, jsonLd}`; `renderBlockNote(blocks, {mediaUrl?})` produces escaped allowlisted HTML, `jsonLdScript(data)` safely serializes JSON for a JSON-LD script. `buildSitemap(pages,site,onSkip?)` produces XML; a page whose SEO data is invalid is skipped and reported through `onSkip` (default: a warning log of slugs and error codes) instead of failing the sitemap. `buildSitemapReport(pages,site)` returns `{xml, skipped:[{id?,slug,code}]}`. An invalid site identity still throws. Pages use `SeoPage` and site `SiteIdentity` types.
- `new AiDraftService(db,{apiKey,baseUrl?,model,transcriptionModel?,monthlyTokenLimit?,allowedClinicalData?,providerName?})`: `draft(task,input,actor)` returns draft text + provenance with mandatory review status; the monthly quota reserves an upper-bound estimate (input bytes + output cap + prompt allowance) before the call, refunds it when the provider fails, and otherwise settles to the provider-reported `usage.total_tokens` (falling back to the estimate when absent; provenance records `reportedTokens` and `chargedTokens`); `transcribe(bytes,mime,actor)` returns a draft transcript. Missing providers throw 503, never fake success. Clinical-data transmission is disabled unless explicitly configured. AI has no release/signing capability.
- `runPublicTool(tool,input,{audience,currency?,serviceFees?})`: validated deterministic tools return a summary, structured values, and email-consent requirements. Clinic deployments must pass audience `patient`; vendor deployments pass `business` and use a separate database. `analyzePublicWebsite(url)` uses `ANALYZER_SOCKET` in production and delegates to the isolated worker. The worker validates all resolved IPs and redirects before bounded fetch, pins the approved address for the connection, and stops after one 15-second deadline covering DNS, connection, every redirect and the body (2 MiB cap). Markup is inspected in a single linear pass. `analyzePublicWebsiteLocal(url, policy?)` accepts a partial `AnalyzerPolicy` for tests only; production code passes nothing and gets the frozen `ANALYZER_POLICY` (public unicast addresses and default ports). `RESTRICTED_IPV4_CIDRS` is the blocked IPv4 list mirrored by `deploy/analyzer-firewall.sh`. It has no clinic credentials and requires the documented host egress firewall.
- `renderFinancialHtml({kind,snapshot},template)` accepts core financial decimal-string snapshots and the typed `FinancialTemplate` described below. `renderFinancialPdf(document,template)` delegates through `PDF_RENDERER_SOCKET` in production; absence of this isolated renderer is an error. Native development may use `renderFinancialPdfLocal`, which loads `playwright-core` on first use (the API does not load it at startup) and requires its Chromium build and disables JavaScript and browser network requests. The production PDF worker also has no container network or clinic provider/database credentials. Always authorize document access at API/domain before rendering; this renderer does not accept arbitrary paths, URLs, or HTML.

`bootstrapTheme()` returns the built-in declarative theme; `themeManifestSchema` and `validateThemeZip` support contract tests and SDK tooling. `THEME_LIMITS` publishes archive budgets. See the [theme development guide](THEME-DEVELOPMENT.md), [format-v1 reference](security/THEME-FORMAT.md), and [deployment runbook](../deploy/README.md).

## Public media and document logos

`new PublicAssetService(db,{root,scanner?})` exposes `upload({bytes,mime,alt},actor)`, `read(id,organizationId)`, and `logoDataUri(id,organizationId)`. The uploader accepts only explicit new public PNG/JPEG/WebP uploads by owner/admin/editor, requires alt text, scans original bytes, and re-encodes a single-frame WebP without EXIF metadata. Its response URL is `/api/v1/public/assets/:id`. Public assets are immutable and stored independently from private files; there is no method to turn an existing clinical/private file public. The logo helper returns a small approved raster data URI suitable for the isolated PDF worker.

`FinancialDocument` supports `invoice`, `payslip`, and `credit-note` snapshots. `FinancialTemplate` accepts `accent`, `font` (`sans`, `system`, `serif`, `mono`), `footer`, `terms`, `showQuantity`, `showLogo`, `columns` (`description`, `quantity`, `unitPrice`, `discount`, `tax`, `total`) and optional vetted `logoDataUri`. Monetary totals remain snapshot values regardless of chosen columns. Unit prices may retain six decimal places; charged totals respect the currency exponent. SVG/remote logos are rejected.

`SeoPage.schemaTypes` applies a maximum of ten applicable preset selections. The generator returns `schemaWarnings` for inapplicable types or missing supporting content, omitting those claims. Custom JSON-LD remains an explicit validated override, but its top-level node types (root `@type` or each `@graph` node) must be applicable to the page type, as for presets; inapplicable nodes are dropped with a warning, and when none remain the generated schema is used. `schemaTypes=[]` emits an empty graph. Citation and medical-review blocks are escaped by the SSR renderer.

## Notifications and scheduling

The domain emits durable `notification.requested` events; the worker checks the recipient's current source-record authorization, category/channel preferences, explicit consent where needed, and quiet hours before creating in-app notifications or queued email. Notifications carry safe titles and protected resource links; email contains no medical/payroll details. Quiet-hour postponement does not consume an error retry. Clinic `notifications.retryLimit` controls bounded delivery attempts.

The scheduler runs once per minute while `OUTBOUND_WORKERS_ENABLED=true`. It creates idempotent 24-hour and 2-hour appointment reminders only for verified linked patient accounts with a latest explicit `reminders` consent. Changed appointment times, cancellation, consent withdrawal, and access revocation are rechecked at delivery. Overdue tasks use their recorded due dates and relevant branch roles; result follow-ups go to the named reviewer and then the covering reviewer after the configured escalation interval. Completed tasks/results suppress stale queued escalation. A missing recorded result due date does not invent a clinical deadline.

Worker startup rejects maintenance and incomplete-restore markers. The BullMQ worker does not consume old jobs while outbound processing is disabled, and each processor rechecks that flag before any effect. Ambiguous SMTP acceptance is held for review rather than automatically sent again. Failures before the mail server accepted the message data are retried with backoff. An administrator retries an ambiguous email only by confirming it was not delivered: `POST /jobs/:id/retry` with `{"confirmNotDelivered":true}` (audited).
